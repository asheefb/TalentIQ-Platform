1. Core Spring Boot Annotations
   1. @SpringBootApplication
        * This is the main annotation used to start a Spring Boot application.
        * It combines 3 different Annotations:
            * @Configuration
            * @EnableAutoConfiguration
            * @ComponentScan
        * With the help of this Annotation 
            * Spring will create required beans
            * Spring will scan your project for components
            * Spring Boot auto-configures your app
        * This annotation reduces boilerplate and makes the main class very clean.
      
   2. @Configuration
        * Declares a class as a configuration class.
        * Used when we want to manually define beans.
        * Instead of using XML configuration, Spring Boot uses this annotation.
        * Any method inside this class with @Bean will return an object managed by Spring.
      
   3. @EnableAutoConfiguration
        * Tells Spring Boot to configure beans automatically based on dependencies.
        * For example:
          * If Spring Boot detects spring-web dependency, it will automatically configure DispatcherServlet(Front Controller in Spring MVC) automatically. 
          * If it sees spring-data-jpa, it configures EntityManager, DataSource, Hibernate automatically.
          * Removes the need for manual configuration. which means Manual Configuration not required.
   
   4. @ComponentScan
      * Instructs Spring to scan packages to find beans/components automatically.
      * It scans for:
        * @Component
        * @Service
        * @Repository
        * @Controller
      * By default, it scans from the package where the main class is located. 
   
   5. @Bean
      * Tells Spring to create and manage an object (bean) returned by the method.
      * Used in a class annotated with @Configuration.
      * Helps when you need custom bean creation.
   
   6. @Component
      * General-purpose stereotype annotation.
      * Marks a class as a Spring-managed component.
      * Spring automatically creates an object (bean) for it.
   7. @Autowired
      * Used for dependency injection.
      * Spring will automatically inject required beans.
      * Works on:
        * Fields
        * Constructors
        * Setter Methods

   8. @Value
      * Injects values from:
        * application.properties
        * environment variables
        * static values
   
   9. @Lazy
      * Tells Spring to create a bean only when needed (not during startup).
      * Improves performance in large applications.
   
   10. @Scope
       * defines how many objects (beans) Spring should create and how long they should live. 
       * Defines bean scope:
         1. singleton (default) - ONE object for the entire application.
            * If 1000 requests come → all use the same single bean.
            * Used for - Services, Repository and Common logic
         2. prototype - Spring creates a new object every time you ask for the bean.
            * User for - Stateful Object, Objects that change frequently, Non-thread-safe objects
         3. request - Spring creates one bean per HTTP request. 
            * After request completes → bean is destroyed.
            * Used for - Request-specific data, Logging request details
         4. session - One bean is created per user session.
            * If the same user makes multiple requests → same bean is reused.
            * Used for: User session data, Shopping cart, User preferences

2. Web Layer Annotations
   1. @RestController
        * Combination of @Controller + @ResponseBody.
        * Used to create REST APIs.
        * Returns JSON/XML directly instead of HTML.
   2. @Controller
        * Handles HTTP requests.
        * Mostly used when returning webpages (Thymeleaf/JSP).
        * For REST APIs, use @RestController instead.
   3. @RequestMapping
        * Used to map URLs at class or method level.
        * Can define: Path, HTTP method, Headers, Params
   4. @GetMapping
        * Shortcut for @RequestMapping(method = GET)
        * Used to handle GET requests.
   5. @PostMapping
        * Handles POST requests.
        * Used for creating new records.
   6. @PutMapping
        * Handles PUT requests.
        * Used for updating existing data.
   7. @DeleteMapping
        * Handles DELETE requests.
        * Used for deleting records.
   8. @PatchMapping
        * Handles partial updates to existing data.
   9. @PathVariable
        * Extracts values from the URL path.
        * Example: /users/{id} → captures id.
   10. @RequestParam
        * Extracts query parameters from URL.
        * Example: /users?age=20 → captures age.
        * @RequestParam is optional if method parameter name matches query param.
        * Use it when:
          * Parameter name differs
          * Parameter is optional
          * Default value is needed
          * Multiple values (List) are expected
   11. @RequestBody
        * Reads incoming JSON (or XML) and converts it into a Java object (DTO).
   12. @ResponseBody
        * Makes a controller method return data directly (JSON).
        * Already included inside @RestController.

3. JPA / Hibernate Annotations
   1. @Entity - Maps a Java class to a database table.
   2. @Table
        * Defines table name and properties.
        * Optional (if class name = table name).
   3. @Id - Marks the primary key field in the entity.
   4. @GeneratedValue 
        * Auto-generates primary key values.
        * Strategies:
            * AUTO - Default. JPA chooses the best strategy based on the database
            * IDENTITY - Database generates the primary key (auto-increment)
            * SEQUENCE - Uses a database sequence to generate IDs
            * TABLE - Uses a separate table to generate IDs
   5. @Column
        * Defines column properties like:
          * name
          * length 
          * nullable 
          * unique 
   6. @Transient - Field not saved to database.
   7. @OneToOne - 
      * Defines 1-to-1 relationship between entities.
      * Ex: Person - Perm Address
   8. @OneToMany 
      * One record mapped to many records.
      * Ex: Teacher - Students
   9. @ManyToOne
        * Many entities relate to one instance of another entity.
        * Ex: Students - Teacher (Many Students belong to one Teacher)
   10. @ManyToMany
        * Many entities relate to many instances of another entity.
        * Requires a join table in DB.
        * Ex: Students & Courses
   11. @JoinColumn - Defines foreign key mapping.
   12. @JoinTable - Defines mapping table for many-to-many mapping.
        * @ManyToMany
          @JoinTable(
              name = "student_course",
              joinColumns = @JoinColumn(name = "student_id"),
              inverseJoinColumns = @JoinColumn(name = "course_id")
          )
          private List<Course> courses;

4. Validation Annotations
   1. @NotNull - Field cannot be null.
   2. @NotBlank 
      * Cannot be blank (used for Strings).
      * Does not allow empty values like " ".
   3. @NotEmpty - Cannot be empty but can have spaces.
   4. @Email - Validates email format.
   5. @Pattern 
      * Validates using regular expression. 
      * Example: mobile number pattern Email Format etc..
   6. @Min AND @Max - Minimum  AND Maximum allowed number value.
   7. @Size - Length/size constraints for strings or lists.

5. Exception Handling Annotations
   1. @RestControllerAdvice
        * Global exception handling for REST APIs.
        * Handles errors for all controllers in one place 
   2. @ExceptionHandler
      * Handles specific exceptions in one place.
      * Used inside @RestControllerAdvice
   3. @ResponseStatus
      * Sets custom HTTP status code when an exception occurs
      * Example: return 404, 400, 500, etc.

✅ 14. Conditional Annotations (Very Important)

These are used when you want a bean to load only when a condition is true.

86. @Conditional

Base annotation for conditional bean creation.

You can attach custom conditions here.

87. @ConditionalOnMissingBean

Bean is created only if the same bean is NOT already present.

88. @ConditionalOnBean

Bean is created only if another expected bean exists.

89. @ConditionalOnClass

Loads bean only if a specific class is on the classpath.

Example:
If Jackson library is present → create JSON converter.

90. @ConditionalOnMissingClass

Opposite of above.

Loads bean only if a class is NOT available.

91. @ConditionalOnProperty

Creates bean based on application.properties value.

Example:
If app.feature.enabled=true, only then the bean loads.

92. @ConditionalOnExpression

Uses SpEL (Spring Expression Language) for conditions.
