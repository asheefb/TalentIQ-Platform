### 1. What are JPA Specifications?
   * JPA Specification is a way to build dynamic, reusable, type-safe queries using code instead of writing many repository methods.
   * In Simple words A reusable condition for querying entities dynamically
   * 👉 Used when:
     * Filters are optional
     * Queries change based on input
     * findBy...And...Or... becomes messy
### 2. Problem Without Specifications
   * Example
     * findByName()
     * findByEmail()
     * findByNameAndStatus()
     * findByEmailAndStatus()
     * findByNameAndEmailAndStatus()
   * Too many methods
   * Hard to maintain
   * Not scalable
### 3. Solution: Specifications
   * Specifications allow you to:
     * Add conditions only when needed
     * Combine conditions dynamically
     * Keep repository clean
### 4. Specification Interface
   * Provided by Spring Data JPA:
     * org.springframework.data.jpa.domain.Specification 
   * Generic Type: Specification<User>
### 5. How Specification Works (Concept)
   * Specification uses:
     * Criteria API
     * Builds SQL queries internally
   * You don’t write SQL. 
   * You write conditions in Java.
### 6. Basic Specification Structure

    ```java
    public static Specification<User> hasName(String name) {
        return (root, query, criteriaBuilder) ->
                criteriaBuilder.equal(root.get("name"), name);
    }

Meaning:
  * root → entity (table)
  * query → current query
  * criteriaBuilder → builds conditions (where, equal, like, etc.)
### 7. Common CriteriaBuilder Methods

   | Method      | Purpose       |
   | ----------- | ------------- |
   | equal       | field = value |
   | like        | field LIKE    |
   | greaterThan | field > value |
   | lessThan    | field < value |
   | in          | field IN (…)  |
   | isNull      | field IS NULL |

### 8. Repository Requirement
To use Specifications, repository must extend:

    JpaSpecificationExecutor<User>
Example:

    public interface UserRepository extends
        JpaRepository<User, Integer>,
        JpaSpecificationExecutor<User> {
    }

### 9. Using Specification in Service

    Specification<User> spec = Specification.where(null);

    if (name != null) {
    spec = spec.and(UserSpecification.hasName(name));
    }
    
    if (isActive != null) {
    spec = spec.and(UserSpecification.isActive(isActive));
    }
    
    List<User> users = userRepository.findAll(spec);

### 10. Why Specification.where(null)?
* Starts with no condition
* Allows chaining .and() / .or() safely

### 11. AND vs OR in Specifications

    spec.and(...)
    spec.or(...)
* and → all conditions must match
* or → any condition matches

### 12. Benefits of Specifications
* Dynamic queries
* Clean repository
* No query explosion
* Easy to maintain
* Perfect for search & filters

### 13. When NOT to use Specifications
* Simple CRUD
* Fixed queries
* Single condition queries

### 14. Real-World Use Cases
* User search filters
* Admin dashboards
* Reports
* Advanced search APIs
* Pagination + sorting + filtering

### 15. Interview One-Liner
Spring Data JPA Specifications allow building dynamic, type-safe queries using Criteria API without writing SQL.
