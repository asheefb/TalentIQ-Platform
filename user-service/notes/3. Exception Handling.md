* Why Global Exception Handling
  * Avoid duplicate try-catch in controllers
  * Centralized error handling
  * Consistent error responses
  
* Why @RestControllerAdvice
  * Applies to all controllers
  * Automatically converts response to JSON
  
* How Validation Errors Are Handled 
  * Spring throws different exceptions based on:
    * HTTP method
    * Request type (@RequestBody, @ModelAttribute, etc.)
  * Validation errors are extracted using:
    * FieldError (most common)
    * BindingResult (optional approach)
  * Returns field-level error messages, not generic errors
* Benefit for Frontend
  * Field-wise error mapping
  * Easy to show validation messages below form fields
  * Cleaner and user-friendly form validation UI

When we use validations at DTO level using validation annotations (Hibernate Validator):
1) For POST/PUT/PATCH → using @RequestBody
   * Example: public Response saveUser(@Valid @RequestBody UserDto dto)
   * if validation fails -> Spring will throw 
        * MethodArgumentNotValidException - Because Spring is validating JSON and converting it into DTO.
        * So we must handle it inside: 
          * @RestControllerAdvice
          * using @ExceptionHandler(MethodArgumentNotValidException.class)
2) For GET → using @ModelAttribute
    * Example:
        * public Response getUsers(@Valid @ModelAttribute FilterDto filter)
        * If validation fails → Spring throws:
            * BindException - Because GET request binds query parameters to an object.

3) When validating @RequestParam or @PathVariable
    * Example:
      * @GetMapping("/user")
        ^ public Response test(@RequestParam @Min(1) int age)
      * If validation fails → Spring throws:
        * ConstraintViolationException - This is method-level validation, not body binding.
4) If wrong data type is passed (NOT validation)
   * Example:
     * @GetMapping("/user/{id}")
       public Response test(@PathVariable Long id)
     * If user passes /user/abc, it can't convert String → Long, so Spring throws:
       * MethodArgumentTypeMismatchException - This is a type conversion error, not validation.
