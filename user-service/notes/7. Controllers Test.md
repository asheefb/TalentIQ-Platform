### 1. Difference Between @ContextConfiguration and @WebMvcTest
1. @ContextConfiguration + @ExtendWith(SpringExtension.class)
    
        @ExtendWith(SpringExtension.class)
        @ContextConfiguration(classes = UserController.class)

* @ExtendWith(SpringExtension.class)
* Integrates JUnit 5 with Spring Test framework
* Enables:
  * Dependency Injection
  * ApplicationContext loading
  * Spring testing features

  Required when using Spring with JUnit 5 (without Spring Boot test slice annotations).

@ContextConfiguration(classes = UserController.class) 
   * Loads only the specified class into the Spring context
   * In this case: UserController
   * Does NOT autoconfigure:
     * MVC setup
     * MockMvc
     * Jackson
     * Validation
     * Exception handlers (unless manually configured)
   * Characteristics
     * Manual configuration
     * Very minimal context
     * No Spring Boot auto-configuration
     * More control, more setup required
     * Common in traditional Spring applications
*  Important
    #### You must manually:
     * Configure MockMvc
     * Mock dependencies
     * Import required beans
2. WebMvcTest(UserController.class)


     @WebMvcTest(UserController.class)
     @Import(GlobalExceptionHandler.class)

* What is @WebMvcTest?
  * A Spring Boot Test Slice Annotation
  * Designed specifically for controller testing
  * Loads only the web layer
* What It Loads Automatically 
  * @Controller
  * @RestController 
  * @ControllerAdvice 
  * MVC configuration 
  * Jackson (JSON support)
  * Validation 
  * MockMvc

* What It Does NOT Load 
  * @Service
  * @Repository
  * Full application context 

  You must mock service layer using @MockBean.

* Why @Import(GlobalExceptionHandler.class)? 
  * Sometimes @WebMvcTest may not auto-detect your global exception handler. 
  * So we explicitly import it:

  
    @Import(GlobalExceptionHandler.class)


This ensures:
* Exception handling logic works in tests
* Custom error responses are tested properly

📊 Side-by-Side Comparison

| Feature            | `@ContextConfiguration` | `@WebMvcTest`      |
| ------------------ | ----------------------- | ------------------ |
| JUnit Integration  | Needs `@ExtendWith`     | Auto-configured    |
| MVC Setup          | ❌ Manual                | ✅ Auto-configured  |
| MockMvc            | ❌ Manual setup          | ✅ Auto-configured  |
| Loads Services     | ❌ No                    | ❌ No               |
| Loads Repositories | ❌ No                    | ❌ No               |
| Best For           | Custom Spring tests     | Controller testing |

* When To Use What?
    * Use @WebMvcTest When:
      * Testing REST controllers 
      * Testing request/response 
      * Testing validation 
      * Testing exception handling 
      * Using MockMvc

      Recommended for Spring Boot controller tests.

Use @ContextConfiguration When:
* You want full control over loaded beans 
* Not using Spring Boot 
* Writing very customized Spring tests

🧠 Simple Summary

* @ContextConfiguration → Manual Spring test setup 
* @WebMvcTest → Spring Boot optimized controller test 
* For Spring Boot → Prefer @WebMvcTest
